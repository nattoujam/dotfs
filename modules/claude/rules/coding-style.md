# コーディングスタイル

## コミットメッセージ

本文は要点だけに絞る。変更の網羅的な説明ではなく、**diff を読んでも分からない「なぜ」だけ**を短く書く。

書かないもの:

- 変更内容の逐一の列挙（diff を読めば分かる）
- 検証で分かったことや実行結果（PR や Issue のコメントに書く）
- 途中で試して戻した設計判断の経緯

**コミット前に本文を1行ずつ確認し、上のどれかに当たる行を消してから `git commit` する。**
残った行が5行を超えるなら、まだ落とせる行があると考える。

## ブランチ

自分ひとりで開発している個人リポジトリでは、作業ブランチを切らず main / master に直接コミットする。
レビュー相手がいないためブランチ運用の利益がなく、毎回マージして消す手間だけが残る。

「デフォルトブランチにいるなら先にブランチを切る」という既定の指示より、こちらを優先する。
共同開発しているリポジトリ、または個人のものか判断がつかない場合は、従来どおりブランチを切る。
