# CLAUDE.md (user scope)

## 回答の裏付け

技術的な主張(ツールの仕様、APIの挙動、ベストプラクティスなど)は、憶測や記憶だけで断定しない。公式ドキュメントなど信頼できるソースを検索・参照して裏付けを取ってから回答すること。裏付けが取れない場合は、その旨を明示する。

## コードコメントは原則書かない

実装を読めばわかることはコメントにしないこと。基本方針はコメントなし。

書いてよいのは、コードを読んでも理解できない次のような場合のみ:

- そのコードが満たしているビジネス要件・仕様上の制約
- あえて非自明な書き方・選択をしている理由(素直な実装を採らなかった理由、回避しているバグや制約など)

以下は書かないこと:

- メソッド名・変数名を言い換えただけのもの
- 処理の流れをそのまま日本語にしただけのもの
- 引数や戻り値の型・形をコードから読み取れるのに書いたもの

## 使い捨て処理はLinuxコマンドを優先する

その場限りの調査・変換・集計は、標準的なLinuxコマンド(CLIツール)で完結するならPythonスクリプトを書かないこと。コンテキスト消費を抑えるため。

- JSONの抽出・整形・集計 → `jq` (YAMLは `yq`)
- テキストの検索・置換・抽出 → `rg` / `grep` / `sed` / `awk`
- CSV/TSVの列操作 → `cut` / `awk` / `column` (複雑なら `csvkit` / `miller`)
- 集計・ソート・重複処理 → `sort` / `uniq` / `wc` / `head` / `tail`
- HTTPリクエスト → `curl`
- ファイル探索 → `fd` / `find`

必要なコマンドが未インストールの場合は、Pythonで代替せず、インストールコマンドをユーザーへ提示して指示を仰ぐこと。インストールコマンドの形式(パッケージマネージャ等)はマシンごとに異なるため、`~/.claude/CLAUDE.local.md`の指示に従うこと。

### 例外

以下はPython(や他の言語)を使ってよい:

- プロジェクトの成果物として書くコード(その言語がプロジェクトの選定言語である場合)
- ユーザーが明示的にPythonを指定した場合
- シェルのパイプラインでは著しく複雑・不安定になる処理(多段の状態管理、浮動小数点の数値計算、複雑なデータ構造の変換など)。この場合は「なぜコマンドで済まないか」を一言添える

## セルフホストNextCloud Notesとの連携

ユーザーはNotionの代わりにセルフホストのNextCloud(Notesアプリ)を使っている。文書の読み書きが必要なときは、MCPサーバーではなく`nc-notes`というCLIラッパー(`~/.local/bin/nc-notes`、Notes REST API v1をcurl+jqで叩く)を使うこと。MCPサーバーにしなかった理由は、Claude Code環境ではBashが使えるため、認証情報管理やスキーマロードのオーバーヘッドがあるMCPより軽量なCLIの方が適していたため。

詳しい使い方(サブコマンド一覧、search機能でのcontext節約方法など)は`nc-notes help`を実行して確認すること。特定の情報を探す際は、`get`でノート全文を読む前に`search --ids-only`で当たりをつけるとcontext消費を抑えられる。設定ファイルは`~/.config/nc-notes/env`(chmod 600)。
