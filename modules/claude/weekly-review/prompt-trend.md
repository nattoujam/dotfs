# トレンドレビュー（長期・一般化向け）

今回は複数月にまたがる長期レビューです。**主軸は時系列の変化と一般化**であり、直近 1 週間の出来事ではありません。

## 何を書くか

1. **推移**：月次・週次で何が増え、何が減ったか。プロンプトの書き方（字数・短文比率・質問比率）、ツール構成、摩擦の量。数値は `digest.md` の推移表から取る
2. **定着したもの / 消えたもの**：初期の月と直近の月で、依頼の内容・進め方・使うツールがどう変わったか。前は毎回言っていたのに言わなくなった指摘、逆に増えた指摘
3. **プロジェクトを横断する不変の癖**：複数プロジェクト・複数月で共通して観測されるもの。これがプロファイルの中核になる
4. **プロジェクト固有の振る舞い**：3 の対比として、特定プロジェクトでしか出ないもの。これは癖ではないと明記する
5. **繰り返し再発している課題**：一度指摘・修正されたのに別の月で再発しているもの。仕組み化が効いていない箇所

## レポートの構成

```
# Claude Code トレンドレビュー <期間>

## サマリ（5 行以内。何が変わり、何が変わっていないか）
## 推移（表と、その読み方）
## 定着した進め方 / 消えた進め方
## プロジェクトを横断する不変の癖
## プロジェクト固有の振る舞い（癖と区別するため）
## 繰り返し再発している課題
## 改善提案（優先順、各項目に「根拠」と「やること」）
## 次の期間の観察ポイント（3 つまで）
```

## profile.md の更新方針

長期レビューはプロファイルの棚卸しを兼ねます。

- 全期間を見直し、3 週 / 2 プロジェクトの基準で「確定した傾向」と「観察中」を並べ替える
- 期間の前半でしか観測されていない項目は「変化・撤回した傾向」へ移す
- 証拠は各項目 2〜4 件に整理する。古い証拠を 1 件は残し、いつから続いているか分かるようにする
- 項目数は「確定した傾向」を 12 件以内に保つ。多すぎるものは統合する

## 長さ

レポートは 3000〜5000 字。
